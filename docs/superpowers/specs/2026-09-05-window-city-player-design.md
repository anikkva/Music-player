# Window — окна в города мира: дизайн

Дата: 2026-09-05 (ревизия 2 — после визуального макета)
Статус: одобрено пользователем, готово к планированию реализации

## Идея

Веб-приложение, где экран — не интерфейс с панелью плеера, а буквально окно в
конкретную локацию (город) реального мира. Единственный элемент управления —
физика самой оконной конструкции: пользователь тянет створку за ручку вниз —
щель растёт, город входит внутрь, звук и картинка проясняются одновременно.
Отпущенная створка остаётся там, где её оставили (без пружинного возврата).
Закрытая створка = только музыка и запотевшее/тусклое стекло; полностью
открытая = городские звуки доминируют, стекло чистое, свет неона падает на
подоконник. Сцена отражает реальные время суток и погоду выбранного города.
Между городами переключаются стрелками/свайпом — с коротким затемнением,
как переход в другую комнату.

Визуальный ориентир зафиксирован рабочим макетом:
[window-mockup.html](/Users/anikkva/Downloads/window-mockup.html) — его
разметка, CSS-переменные и JS-логика (drag створки, canvas-дождь, генерация
скайлайна, конфиг городов) переносятся в реализацию почти без изменений и
разбиваются на модули (см. «Архитектура»).

Метаданные на подоконнике — без капслока и цифр, «гравировкой»:

```
Tokyo
Shibuya

21:43        Rain 18°

music ───────●──── city   (волосок-индикатор баланса, без процентов)
```

## Область MVP

- 3 города: **Tokyo/Shibuya**, **Paris**, **New York** — выбраны для демонстрации
  разных сочетаний времени суток, погоды, музыки и звука. Архитектура рассчитана
  на добавление городов позже без изменения основной логики.
- Аудио — стриминг по прямым URL. Для MVP используются публичные/примерные
  амбиент- и музыкальные треки (по одному музыкальному + одному городскому на
  город), которые пользователь сможет позже заменить своими ссылками — это
  отдельный конфиг, не часть логики.
- Реальные данные времени и погоды (не имитация) — это принципиально для идеи
  «настоящее окно в настоящий город».
- Полный набор функций плеера: play/pause, следующий/предыдущий город, seek
  (для музыкального слоя), громкость, список локаций, метаданные (город,
  район, время, погода), анимация окна и сцены. Отдельной «звуковой
  визуализации» нет — её роль играют запотевание стекла и яркость неона
  (см. «Данные и визуал»).
- Одна механика открытия окна для всех городов (створка едет вниз); разница
  между городами — палитра, неон, интенсивность дождя, цвет рамы (как в
  объекте `CITIES` макета). Разные типы конструкции окна (раздвижная,
  распашная, гильотина) — сознательно не в MVP, см. «Вне рамок MVP».

## Архитектура

Статический сайт на чистом JS (ES-модули), без сборки и фреймворка — выбран
после сравнения с React+Vite и React+продвинутый визуал: для 3 окон и одной
основной механики (слайдер + кроссфейд + canvas-сцена) компонентный фреймворк
избыточен, а логика (`weather.js`, `audioEngine.js`, конфиг городов) при
необходимости позже переносится в React почти без изменений.

```
music-player/
├── index.html
├── styles/style.css
├── src/
│   ├── main.js          — точка входа: карусель городов, слайдер, кнопка "включить"
│   ├── cities.js        — конфиг: 3 города (координаты, таймзона, район,
│   │                       URL музыки/эмбиента, цветовая палитра)
│   ├── weather.js       — fetch к Open-Meteo, маппинг weathercode → condition
│   ├── time.js          — локальное время города (Intl timeZone), бакет
│   │                       времени суток (ночь/рассвет/день/закат)
│   ├── audioEngine.js   — Web Audio: 2 источника на GainNode, equal-power
│   │                       кроссфейд по значению открытости створки
│   └── windowScene.js   — Canvas/CSS-рендер сцены: небо по времени/погоде,
│                            дождь частицы (из макета), запотевание стекла и
│                            яркость неона по значению открытости
```

Каждый город — независимый объект в `cities.js`; добавление нового города —
один новый элемент массива.

## Данные и визуал

- **Время**: `Intl.DateTimeFormat` с `timeZone` города (`Asia/Tokyo`,
  `Europe/Paris`, `America/New_York`) — вычисляется на клиенте, без API,
  всегда точное.
- **Погода**: [Open-Meteo](https://open-meteo.com/) (бесплатно, без ключа) по
  координатам города. Запрос при загрузке страницы + обновление раз в 10
  минут. `weathercode` маппится в категорию сцены (clear/rain/snow/clouds/fog)
  и в текст для метаданных ("Rain", "18°C").
- **Створка = слайдер**: нет отдельного UI-контрола — верхняя створка окна
  перетаскивается за ручку (`pointerdown`/`pointermove`/`pointerup`), а также
  управляется клавиатурой (↑/↓ на сфокусированной створке, `role="slider"` +
  ARIA `aria-valuenow` для доступности — как в макете). Значение открытости
  0..1 не имеет числового отображения в UI.
- **Аудио-слои**: у каждого города два аудио-источника — музыка и городской
  эмбиент, оба зациклены и играют параллельно с момента старта. Значение
  открытости створки задаёт равномощный (equal-power) кроссфейд громкостей:
  0 = только музыка, 1 = город доминирует, между ними — плавный переход.
- **Визуал = слышимый баланс**: отдельной звуковой визуализации (амплитуда,
  бары) нет. Баланс виден напрямую через состояние сцены, управляемое тем же
  значением открытости: закрытая створка — стекло размыто/обесцвечено/темнее
  (конденсат, `.haze`), дождь на canvas реже и тише; по мере открытия стекло
  проясняется, дождь усиливается, неон на подоконнике становится ярче
  (`.sill::before`). Кроссфейд одновременно слышен и виден.
- **Баланс на подоконнике**: волосок-индикатор (`.balance .track`) с точкой,
  бегущей от подписи «music» к «city» пропорционально открытости — без цифр
  и процентов.
- **Типографика и цвет**: единственная гарнитура — variable Archivo (wdth/wght
  оси), имя города — крупно и растянуто по нижнему краю стекла, район/время/
  погода — тем же шрифтом, узко и мелко. Палитра (небо, кирпич, свет окон,
  неон, цвет рамы, интенсивность дождя) целиком задаётся per-city конфигом в
  `cities.js`; остальной UI — монохромный полупрозрачно-белый.
- **Навигация между городами**: стрелки (клик или ←/→ на клавиатуре) и свайп
  на тач-устройствах; переход сопровождается коротким затемнением окна перед
  сменой рамы/сцены (`.window.dim`), а не мгновенной подменой.
- **Плеер-контролы**: play/pause общего аудио-состояния (кнопка запуска, см.
  «Обработка ошибок»), next/prev город, seek по музыкальному треку, громкость
  (master, отдельно от открытости створки — это разные оси: master влияет на
  общую громкость, открытость — на баланс между слоями).

## Обработка ошибок

- **Автоплей заблокирован браузером** — аудио не стартует без явного жеста.
  Показывается оверлей "Открыть окно" / power-кнопка; `AudioContext`
  создаётся и звук стартует только по клику пользователя.
- **Погода не загрузилась** (сеть/таймаут) — тихий фолбэк: нейтральное
  состояние ("Clear · —°C"), сцена рендерится по времени суток без осадков;
  ошибка не блокирует остальной интерфейс.
- **Плейсхолдер-аудио недоступно/долго грузится** — сцена мягко
  затемняется/приглушается до начала воспроизведения; не блокирует
  переключение между городами.

## Тестирование

Проект в основном визуально-интерактивный (аудио + canvas-анимация), поэтому
автоматические тесты ограничены чистой логикой без DOM/audio API:

- `time.js` — маппинг часа локального времени → бакет времени суток.
- `weather.js` — маппинг `weathercode` → condition.
- `audioEngine.js` — формула равномощного кроссфейда (gain по значению
  слайдера).

Эти функции покрываются модульными тестами через встроенный `node --test`
(без Jest/Vitest — не нужен тест-фреймворк ради трёх чистых функций).
Механика взаимодействия (слайдер, canvas-анимация, переключение городов,
реальный fetch погоды) проверяется вручную в браузере после реализации.

## Явно вне рамок MVP (YAGNI)

- Импорт плейлиста из файла, редактирование списка городов через UI —
  список городов захардкожен в `cities.js`.
- Бэкенд/сервер — всё выполняется в браузере.
- Аккаунты пользователей, сохранение прогресса между сессиями.
- Более 3 городов, глобус/карта как основной экран навигации.
- Разные физические конструкции окна по городам (раздвижная алюминиевая рама
  для Токио, распашная двустворка на эспаньолетке для Парижа, гильотина для
  Нью-Йорка) — в MVP все три используют одну механику (створка едет вниз),
  разница только в палитре/неоне/дожде/раме. Разные конструкции — материал
  для будущей итерации, архитектура (per-city конфиг в `cities.js`) готова к
  этому расширению, но не реализует его сейчас.
- Пружинный/«дышащий» возврат створки после отпускания — створка остаётся
  ровно в той позиции, где её отпустили.
