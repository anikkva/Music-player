# Window — окна в города мира: дизайн

Дата: 2026-09-05
Статус: одобрено пользователем, готово к планированию реализации

## Идея

Веб-приложение, где экран выглядит как настоящее окно в конкретную локацию (город)
реального мира. Пользователь регулирует степень «открытости» окна вертикальным
слайдером: закрытое окно — играет только музыка, полностью открытое — доминируют
звуки города. Сцена в окне отражает реальные время суток и погоду выбранного
города. Между городами переключаются горизонтальным свайпом/скроллом.

Пример отображаемых метаданных:

```
TOKYO · SHIBUYA
21:43 · Rain · 18°C

🎵 Music — 40%
🌃 City — 60%
```

## Область MVP

- 3 города: **Tokyo/Shibuya**, **Paris**, **New York** — выбраны для демонстрации
  разных сочетаний времени суток, погоды, музыки и звука. Архитектура рассчитана
  на добавление городов позже без изменения основной логики.
- Аудио — стриминг по прямым URL. Для MVP используются публичные/примерные
  амбиент- и музыкальные треки (по одному музыкальному + одному городскому на
  город), которые пользователь сможет позже заменить своими ссылками — это
  отдельный конфиг, не часть логики.
- Реальные данные времени и погоды (не имитация) — это принципиально для идеи
  «настоящее окно в настоящий город».
- Полный набор функций плеера: play/pause, следующий/предыдущий город, seek
  (для музыкального слоя), громкость, список локаций, звуковая визуализация,
  метаданные (город, район, время, погода), анимация окна и сцены.

## Архитектура

Статический сайт на чистом JS (ES-модули), без сборки и фреймворка — выбран
после сравнения с React+Vite и React+продвинутый визуал: для 3 окон и одной
основной механики (слайдер + кроссфейд + canvas-сцена) компонентный фреймворк
избыточен, а логика (`weather.js`, `audioEngine.js`, конфиг городов) при
необходимости позже переносится в React почти без изменений.

```
music-player/
├── index.html
├── styles/style.css
├── src/
│   ├── main.js          — точка входа: карусель городов, слайдер, кнопка "включить"
│   ├── cities.js        — конфиг: 3 города (координаты, таймзона, район,
│   │                       URL музыки/эмбиента, цветовая палитра)
│   ├── weather.js       — fetch к Open-Meteo, маппинг weathercode → condition
│   ├── time.js          — локальное время города (Intl timeZone), бакет
│   │                       времени суток (ночь/рассвет/день/закат)
│   ├── audioEngine.js   — Web Audio: 2 источника на GainNode, кроссфейд по
│   │                       слайдеру, AnalyserNode → амплитуда
│   └── windowScene.js   — Canvas-рендер сцены: небо по времени/погоде,
│                            дождь/снег частицы, неон-пульс от амплитуды
```

Каждый город — независимый объект в `cities.js`; добавление нового города —
один новый элемент массива.

## Данные и визуал

- **Время**: `Intl.DateTimeFormat` с `timeZone` города (`Asia/Tokyo`,
  `Europe/Paris`, `America/New_York`) — вычисляется на клиенте, без API,
  всегда точное.
- **Погода**: [Open-Meteo](https://open-meteo.com/) (бесплатно, без ключа) по
  координатам города. Запрос при загрузке страницы + обновление раз в 10
  минут. `weathercode` маппится в категорию сцены (clear/rain/snow/clouds/fog)
  и в текст для метаданных ("Rain", "18°C").
- **Аудио-слои**: у каждого города два аудио-источника — музыка и городской
  эмбиент, оба зациклены и играют параллельно с момента старта. Вертикальный
  слайдер (0–100%, визуально стилизован под оконную створку) задаёт
  равномощный (equal-power) кроссфейд громкостей: 0% = только музыка,
  100% = город доминирует, между ними — плавный переход.
- **Визуализация звука**: `AnalyserNode` на каждом аудио-слое отдаёт амплитуду
  в реальном времени в `windowScene`. Амплитуда музыки модулирует пульсацию
  неона/света в сцене; амплитуда города — интенсивность дождя и «шевеление»
  окон домов. Отдельных баров/волн нет — визуализация встроена в саму сцену
  (light on window sill, деревья).
- **Навигация между городами**: горизонтальный scroll-snap контейнер — свайп
  на тач-устройствах, стрелки/скролл-колесо на десктопе.
- **Плеер-контролы**: play/pause общего аудио-состояния, next/prev город
  (совпадает с горизонтальной навигацией), seek по музыкальному треку,
  громкость (master, отдельно от баланса слайдера окна).

## Обработка ошибок

- **Автоплей заблокирован браузером** — аудио не стартует без явного жеста.
  Показывается оверлей "Открыть окно" / power-кнопка; `AudioContext`
  создаётся и звук стартует только по клику пользователя.
- **Погода не загрузилась** (сеть/таймаут) — тихий фолбэк: нейтральное
  состояние ("Clear · —°C"), сцена рендерится по времени суток без осадков;
  ошибка не блокирует остальной интерфейс.
- **CORS зажимает аудио-поток** (AnalyserNode не может читать данные с
  «заражённого» кросс-доменного источника без корректных CORS-заголовков) —
  перехватываем исключение при подключении анализатора и переключаемся на
  процедурную имитацию пульса (синус от времени) вместо реальной амплитуды;
  визуал не ломается, но менее "живой".
- **Плейсхолдер-аудио недоступно/долго грузится** — сцена мягко
  затемняется/приглушается до начала воспроизведения; не блокирует
  переключение между городами.

## Тестирование

Проект в основном визуально-интерактивный (аудио + canvas-анимация), поэтому
автоматические тесты ограничены чистой логикой без DOM/audio API:

- `time.js` — маппинг часа локального времени → бакет времени суток.
- `weather.js` — маппинг `weathercode` → condition.
- `audioEngine.js` — формула равномощного кроссфейда (gain по значению
  слайдера).

Эти функции покрываются модульными тестами через встроенный `node --test`
(без Jest/Vitest — не нужен тест-фреймворк ради трёх чистых функций).
Механика взаимодействия (слайдер, canvas-анимация, переключение городов,
реальный fetch погоды) проверяется вручную в браузере после реализации.

## Явно вне рамок MVP (YAGNI)

- Импорт плейлиста из файла, редактирование списка городов через UI —
  список городов захардкожен в `cities.js`.
- Бэкенд/сервер — всё выполняется в браузере.
- Аккаунты пользователей, сохранение прогресса между сессиями.
- Более 3 городов, глобус/карта как основной экран навигации.
